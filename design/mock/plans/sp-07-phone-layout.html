SP-07 Phone layout pass

Goal

Every project tab works on a phone that is 390 pixels wide. The owner can answer a question, allow a command and read a diff without zooming or scrolling sideways.

SP-04 checked keyboard navigation and found the phone problems listed below. This sprint fixes them. It starts after SP-04 merges, because both sprints change packages/web/src/shell/.

What changes at 390 pixels

The sidebar folds into a menu button. The top bar keeps three things: the menu, the current place and the bell. The branch picker moves into the menu.

The board shows one ordered list instead of columns. Each sprint keeps its status, its label and its name on one line. A tap opens the sprint page.

Tables keep their first column and move the rest into a second line. The second line starts with the status, because the status is what the owner looks for first.

Pages with their own cases

Git keeps a 16 pixel gutter on each side, so a swipe from the edge still goes back. It shows the file list first and the diff after a tap.

The service pages and the Mocks tab have their own layouts. Machines, Subscriptions and Service settings follow the table rule above. Mocks shows one screen at a time, with its name above it.

Browser checks

The browser tests open every project tab at 390, 768, 1440 and 2560 pixels, in light and dark mode. Each check fails when the page scrolls sideways or when a button is smaller than 44 pixels.

The existing desktop checks stay unchanged. A failing desktop check blocks the merge.

Evidence

The Test runner records a screenshot of each tab at 390 pixels and attaches it to the sprint. The Reviewer compares them with the screens in design/lgtm.fig.

The sprint is done when the full run passes and the review round finds no blocker.

Out of scope

  • The phone app is a separate project, Phone companion.
  • Tablet layouts between 768 and 1024 pixels wait for a later sprint.
