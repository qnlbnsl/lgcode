# LGTM Studio Preview — Implementation Brief

Balanced summary of Kunal’s walkthrough feedback. Use this as the source of truth for UX/product changes. Prefer redesign over patching denseness. Treat GitHub Projects / Actions as the reference bar where noted.

---

## North-star principles

1. **One job per surface.** Needs Attention = triage. Repositories/projects = navigation. Don’t duplicate the same list in three places.
2. **Less density, less redundancy.** Remove copy that repeats the row title, explains the system to the user, or sounds conversational on a button.
3. **Empty states keep structure.** Never replace a board/timeline/list with a blank alternate page—show the real layout empty.
4. **You talk to the project lead.** Builders and test runners are not interactive control surfaces; they’re observability.
5. **Agent/UI copy is not UI chrome.** Don’t put instructional sentences where titles belong. Buttons are nouns/verbs, not spoken sentences.

---

## 1. Home / Needs Attention (major redesign)

### Problems
- Hero stats (“6 requests need you”, longest wait, “9 agents working”) feel optional/oversized.
- Needs Attention does two jobs: triage + projects overview.
- Project chips/rows navigate away instead of expanding context.
- Expanded issue cards are too dense and redundant.

### Target layout
1. **Top: sortable/filterable Needs Attention table** (Excel-like columns: title, project/repo, stage/status, wait time, type, etc.).
2. **Optional compact status strip** for counts—smaller; if filters cover it, drop the large “6 requests…” block or fold its info into table columns/filters.
3. **Remove the projects subsection from Needs Attention.** Project navigation belongs in the left sidebar / All Projects. If projects were only there to contextualize attention items, replace that with richer row fields (repo, project, stage) + filters.

### Expanded issue card rules (e.g. failed start)
- Label the long explanation as **Description**, not a second title (title already says the issue).
- **Primary actions only:** e.g. “Sign in on Buildbox”, “Open in thread”. Keep **Resume** only if it is a real recovery path after external fix; don’t present three near-duplicates.
- Remove the redundant meta row that repeats agent/team already shown in the parent row (“Builder → Build Team”).
- **Phone notification CTA:** don’t leave the current sprawling banner. Re-evaluate with UI skills—prefer a compact top-of-page or settings-adjacent prompt (“Set up” / “Not now”), not a wide empty horizontal strip.

### Info architecture follow-up
- Clarify (and likely consolidate) **Needs Attention vs Questions vs Approvals.** If Needs Attention already surfaces what needs the user, Questions/Approvals as separate top-level pages are redundant unless they add a distinct filtered view.

## 2. All Projects

- Fine as a destination; feels duplicated while Needs Attention also lists projects—fix by removing projects from Needs Attention (above).

---

## 3. Global search (“Find project or agent”)

### Remove
- Subcopy like “Projects and what needs you.”

### Behavior
- Results are a dynamic ranked list: **repositories → projects → agents/workers**.
- Query like “LGTM Studio” → repo first; “LGTM Studio agent” → agent console under that repo/project.
- Move beyond naive keyword match: **local embeddings + vector search** (small CPU model; optional pgvector). Index project goals, descriptions, repo metadata, agent names so fuzzy/natural queries work (“which project was working on the git worktree?”).
- As projects evolve, **keep description/goal updated** so the index stays useful (ties to New Project below).

---

## 4. Left sidebar

- Rename top level from **Projects → Repositories**.
- Under each repository: **projects** (and teams/agents as children as appropriate).
- **Double-click** a collapsed row → expand; double-click expanded → collapse. (Single-click can still select/navigate—define clearly.)
- On repository selection: keep list, but add a **running product description** under remote/base branch. Replace awkward “on” label with clearer wording (e.g. base branch / tracking branch).

---

## 5. New Project

- Replace freeform **project name** with **Goal** (first message to the lead agent). Example: “Make a mock for LGTM Studio mobile app.”
- Lead agent’s first step: call a tool to **set the project name**; user shouldn’t invent names.
- Show **available models** as their own column (alongside lead subscription / Claude Code team).
- Nightly job (~00:00): refresh available models per supported harness.
- Goal text should be searchable via the vector index (Cmd-K).

---

## 6. Project page / Kanban

### Keep / improve
- Kanban is the right centerpiece. Model after **GitHub Projects**: backlog, priority, team items, roadmap, epics, board types.
- Redesign top chrome (Design / Plan / Build / Review / Handover) toward that model; a project is **one or more epics under a single goal**.

### Layout bugs
- Opening the project-lead sidebar must **not reflow card spacing**. Board is its own full entity; sidebar overlays/slides without resizing the board geometry.
- Add a **focus/fullscreen** control that hides sidebars + chat so the board can be worked full-bleed.

### Empty projects (e.g. Phone Companion)
- Always show the **empty Kanban** (lanes present, no cards)—not a “no sprint yet” alternate page. Same for review rounds, test runs, etc.: preserve structure; fill as the lead works.

---

## 7. Design tab (major, needs design partnership)

### Intent
- Near-fullscreen **Open Pencil** (or equivalent) canvas.
- Thin top chrome: **category dropdown → secondary dropdown** (e.g. Screens → Onboarding screens; Design palette → CSS/buttons vs components).
- Show full design file content (screens, components, palette)—not a half-empty shell.
- Requires a **standard for how Figma/design files are stored and mapped** into these categories. Involve design lead (“Apple Hat”) to define taxonomy; engineering shouldn’t invent the design system IA alone.

---

## 8. Workflow page

- Fix the fake-title pattern: “Phase 4 of 8, build 1 of 7 sprint start” is status metadata, not a display title—restyle as secondary status, not large title-weight type.
- Timeline blocks (Define, Design, Build…) are good.
- Detail panels: break the wall of text; clearer sectioning.
- Agent groups: **Waiting / Working / Idle** with rules:
  - Hide empty Waiting.
  - Prefer always showing Working and Idle when any agents exist; hide Working/Idle only when empty if something else remains.
  - If zero agents: single “Agents” section → “No agents running.”

---

## 9. Review rounds

- Liked overall. Fix visual weight: large cards vs tiny left color bar—rebalance.
- Audit and remove unnecessary copy.

---

## 10. Test runs

- Remove instructional subtitle copy (“merge needs a passing report…”, “full runs use pnpm check”). Command/config lives with project lead / project settings—not hardcoded UI copy.
- Users **do not operate** test runners or builders. Page is for **status + logs** (GitHub Actions / PR checks style).
- “Start full run” invokes whatever the project has configured—no UI rewrite per stack.

---

## 11. End result

- Same anti-pattern: statement-as-title / subtitle—remove or demote.
- Button copy: not conversational. Prefer “Change result” / “Request change” over “Ask the project lead to change it.”

---

## 12. Mocks

- Feels half-baked. Match **workflow secondary-tab spacing**. Rebuild with real empty/populated structure.

---

## 13. Chat (project lead)

- **User messages right, lead left** (iMessage-style).
- Improve question/approval affordances: border/background, clear interactive cards—not bare clickable text.
- Clicking a question should **not silently switch to another chat** without clarity. Preferred patterns:
  - Open that agent thread in the sidebar focused on the question; answer there; thread can close when done; **or**
  - Inline card: answer / accept recommendation / “Need to chat” → then route to the agent.
- When navigating to another agent (e.g. build lead), **top bar must reflect the active agent**—don’t leave project-lead chrome looking unchanged.

---

## 14. Message board / Agents / Terminal

- Message board: OK. Direct-message overlapping icons feel odd—prefer icon + spacing + icon (dash between) if keeping dual avatars.
- Agents: good for now.
- Terminal: good.

---

## 15. Git page

- Add **auto commit message**: cheap model on the diff (user-configurable in service/settings; prompt forbids attribution fluff; short conventional commit).
- Same model for **PR title + description** from commit list; respect PR title character limits.
- First-run / settings: pick model for git message + PR generation.

---

## 16. Settings

- Keep overall page; extend:
  - Lead subscription: choose **model** (+ **effort** when the model supports it).
  - Teams / harnesses: don’t require awkward multi-select of all harnesses. Default to user’s available harnesses. Prefer a **proposed assignment table** (plans / reviews / etc. → harness + model + effort) that the lead presents for approval; user can override (e.g. “use Claude Fable everywhere”).

## Suggested implementation order

| Priority | Area | Why |
|---|---|---|
| P0 | Needs Attention redesign + IA (drop projects block; filters; card cleanup) | Highest daily friction |
| P0 | Sidebar rename Repositories → Projects; empty Kanban/structure everywhere | Mental model + empty-state consistency |
| P0 | Chat alignment + question/approval UX + agent chrome identity | Core interaction |
| P1 | New Project = Goal + agent names project; model column | Creation flow |
| P1 | Kanban spacing/fullscreen; GitHub Projects–inspired board chrome | Core project workspace |
| P1 | Workflow/Test/End-result copy & hierarchy cleanup | Quick polish, high clarity |
| P2 | Vector search / local embeddings | Bigger infra; huge search payoff |
| P2 | Design tab Open Pencil + taxonomy | Needs design partner |
| P2 | Auto commit/PR messages + settings model/effort/harness table | Power-user polish |
| P3 | DM icon treatment; mocks rebuild; Questions/Approvals consolidation | Secondary |

---

## Explicit non-goals / constraints for implementers

- Do not add more explanatory prose into titles or button labels.
- Do not make builders/test runners user-operated consoles.
- Do not hide primary UI when data is empty—show empty structure.
- Do not invent Figma/design taxonomy without design ownership.
- Prefer filterable tables and GitHub-like patterns over custom dense dashboards.
